# Finite hearth ash cleanup

[Canonical Soul Actions direction](https://github.com/soulsimulation/souls/blob/647d04a5ce5621717c2fad78c153d082e3dffcb2/docs/design/soul-actions-direction.md): breadth and basic coherence, ordinary bounded implementation and mandatory verification.

`core/ash-hearth@1` starts with four supplied spent-ash units. With the hearth off and empty hands, `clean-ash` performs four seconds of existing native operate work. Completion transfers up to the remaining capacity of the same actual supported `core/ash-bucket@1`. The source and bucket change atomically, with started actor/body, identities, support, pose and state rechecked. Interruptions and refused commits preserve both materials. This is finite supplied material, without a burn clock, ash generation or scientific combustion model.

Read the hearth for its own current stock, requirements and historical cleanup credit. Inspect the bucket for its own current contents. Clearing all ash enables existing native hand-contact light/put-out actions. The same filled bucket can be carried and put down normally. No nested output object is created. New definitions are opt-in local fixtures; released definitions and framework contracts remain unchanged.

Cold-ID regression sends exact literal IDs from fresh actors without first listing offers. It checks requested/bound target identity, useful blocked light/off/bucket reasons, and a valid distant cleanup walking to the same hearth. This bounds the new native fixture; it does not claim the shared production catalog/binding issues tracked in #1737 and #1751 are repaired.
