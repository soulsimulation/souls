# Native vertical training

Place `core/stair-training@1` beside the lower landing of an existing entity with one usable native stair link.
The marker does not create stairs or terrain. Use its normal `ascend` operation with the flight's ordinary
reference in `text`. Existing native walking reaches the actual lower and upper endpoints; the native planner
remains authoritative. Completed ascent records the same trainee/body/flight and actual native upper elevation.
The same trainee at that upper landing then uses `descend`; completed native descent and return to the marker
credits one durable round. Repeat those two operations for further rounds.

Current `stairTraining` inspection facts show stage, flight, pending trainee and observed upper elevation,
completed count, latest participant and actual rise/descent. Permission to marker and flight, empty hands and
unchanged targets/native link are rechecked. Interrupted or failed work earns no credit. A trainee who leaves
the upper landing must return there to descend the recorded flight, or return to the marker and reset without
credit. Pending and completed records persist; unfinished programmes earn nothing merely from elapsed time.

A real rise/descent must exceed the existing native STEP_UP domain, not a new contact tolerance. This is
training over existing supported navigation, not a new gait, forced route, teleport or physiological simulation.
