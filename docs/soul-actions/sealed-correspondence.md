# Sealed correspondence

`core/sealed-correspondence@1` is one actual carryable envelope/message entity. Discover its normal object offers,
write a message (up to240characters), seal it, and break/open the seal once. The state only advances
blank→written→sealed→opened. Red wax is whole while sealed and split after opening; an opened seal cannot be
resealed and the message cannot be rewritten.

Walk close first and set down any held item; the correspondence-only admission guard refuses distant or occupied-hand operation. Actions use existing admission semantics with a short native craft motion: state commits when admitted, and stopping later keeps
that admitted change. This does not claim precise hand contact, completion timing or physical tearing. Set the
letter down before operating; native pickup/putdown and existing access/ownership remain authoritative.

Normal `inspect` reads the current `correspondence` facts: full message and integrity stage. Available
compose/seal/open offers also follow current authoritative guards. This object does not expose the generic sign
reader; that separate stale-read limitation is not repaired here. The message is readable even when sealed:
this is visible integrity state, not confidentiality, cryptographic authentication or a multi-Soul delivery system.
Message and integrity remain on the same entity across native handling, snapshots and process restart.

Only nearby discovery adds the bounded three object offers and read; no idle scans or model work are added.
[Canonical Soul Actions direction](https://github.com/soulsimulation/souls/blob/647d04a5ce5621717c2fad78c153d082e3dffcb2/docs/design/soul-actions-direction.md)
keeps basic coherence and existing mandatory checks; fine grips are optional polish.
