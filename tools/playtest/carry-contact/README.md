# Final-draw carry contact

`oracle.mjs` observes the production renderer without changing its poses, timing or render calls. Install `contactTools` with Playwright's `page.evaluate`, supplying the production people-kit URL, the actual Soul/body/load bindings, the served kind entry and source provenance. Activate `window.__carryContactObserver.active` only during the intended contact interval, then call `stop()` and retain its bounded result.

Every on-screen world render is graded. Raw observations are bounded to 100 (first 50 and rolling latest 50), with eight first failure witnesses, aggregate counts and per-hand maxima continuing after that cap. First and last draw/frame/world/performance stamps bound the measured interval. Shadow, reflection and offscreen renders are excluded. Palms come from the current production wrist transforms after the draw. An instanced load's root is recovered independently from every rendered part, including its mesh parent and authored geometry offset; an unrendered placeholder cannot supply the load transform. Declared millimetre grip points are transformed into metres through that root.

A native authoritative assignment must identify both required hands and their grip names at the sampled world time before a contact result can pass. Either assigned hand missing or more than 3 cm away fails. Current streams do not supply that assignment. Without it, each reported nearest-declared-grip distance is only a lower bound: both palms of one carrier farther than 3 cm from every declared grip prove a miss; any other result remains unproved. The tool does not certify collisions, naturalness, load balance or native positions.

Run the focused fixtures with `node --test tools/playtest/carry-contact/oracle.test.mjs`.

`local.mjs <ignored-output-directory>` boots the existing Mars camp, pairs two ordinary commanded clients and uses their ordinary carry commands on the existing first pallet. It requires explicit prebuilt current-source `V2_BIN`, `V2_REPLICA_PKG`, `SOULS_REPLICA_PKG`, `V2_WEB` and existing `MARS_WEB_DIR`. It writes a setup screenshot and waits for a `go` file before lifting. A reviewed `binding-private.json` must name the exact served entry file, its SHA-256, native load/kind, page entity and Soul/body mappings. Neither file changes the world. Use actual camera controls to frame the subjects before approving the lift. While held for review, a `review-private.json` with a new `id` can request a real `button` click (`name`), a real `key` hold (`key`, `ms`, at most 3000), or a `shot`; each writes an original setup screenshot. The measured page is that same reviewed page. `CARRY_ARTIFACT_MANIFEST` names the build provenance JSON; its `source` identifies the built product, independently of later tool commits. The runner activates only after the reviewed lift, measures a three-second stationary interval, sets down, leaves, quits clients and stops its world and browser. This narrow baseline does not certify entry, travel or set-down continuity. Outputs remain ignored and are never committed.
